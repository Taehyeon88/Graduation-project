# 13. 성장 시스템 (영웅 승급 + 공용 트리, 키워드 연계)

> 성장은 XCOM 2식 **영웅 승급(깊이)** 과 킹덤러시식 **공용 트리(폭)** 두 층이다. 덱이 5~8장으로 작고 영웅이 계속 남기 때문에, 원작의 "특성 2개 + 소문 1개" 구조를 영웅 한 명 한 명이 깊어지는 방향으로 바꾼다.
> 원본: Claude Docs [「졸업작품 기획 결정 정리 — 스테이지형 전환」](https://claude.ai/artifact/Jze3unwnJ26XAPB113egh5) "성장 시스템", 세부는 Claude Docs [「성장 시스템 기획서」](https://claude.ai/artifact/YX5EgvvfeFpoQxHTWDjK7B) (rev 21 기준). 구현 항목: [task-list.md](../task-list.md) T-10~T-13.
> **상태: 영웅 승급 구현됨(§5, 2026-11-16) / 공용 트리·교체형 소문 미구현.** 1장은 첫 기획 결정 기록이며, 승급 규칙은 「성장 시스템 기획서」(§5)가 대체한다 — 둘이 다르면 §5가 최신.

## 1. 확정 사항 (기획서)

### 1-1. 원작 대비 변경

| 항목 | 원작 | 변경안 |
|---|---|---|
| 특성 | 최대 2개, 획득 위주 | ~~고유 특성 1개(고정) + 승급 특성 2~3개(승급마다 2택1)~~ → **특성 칸 2개 유지, 승급마다 "새 특성 / 특성 강화" 2택1, 최대 2단계** (§5, 「성장 시스템 기획서」) |
| 소문 | 1개, 이벤트로 획득 | 영웅당 1칸, 스테이지 전에 교체할 수 있는 연계 장치 |
| 시너지 | 팀 전체, 유물 | 영웅 2~3명 사이의 키워드 연계 |

### 1-2. 성장의 두 층

| 층 | 벤치마크 | 재화 | 성장 내용 | 재배분 |
|---|---|---|---|---|
| 영웅 승급 (깊이) | XCOM 2 | 승급 휘장 — 스테이지 첫 클리어 보상 (총량 고정) | 승급마다 특성 2택1. 같은 영웅도 플레이어마다 다른 역할 | - |
| 공용 트리 (폭) | 킹덤러시 | 별 — 별 목표 보상 (총량 고정) | 클래스 공통 효과와 덱 규칙. 예: 원거리 사거리 +1, 덱 슬롯 +1, 전투 중 리롤 +1, 소문 칸 해금 | 언제든 무료 |

- 휘장은 "누구를 키울지", 별은 "어떤 방식으로 싸울지"를 정한다. 둘 다 총량 고정이라 디자이너가 각 스테이지 시점의 전력을 예측할 수 있다.
- 별은 성장 후 이전 스테이지로 돌아가 남은 별을 회수하는 반복 플레이 동기가 된다.

### 1-3. 키워드 연계

> 「성장 시스템 기획서」(rev 21)의 승급 특성에는 키워드(표식·도발)가 없다 — 아래는 첫 기획 결정 기록으로만 남기고, T-15(키워드 프로토타입)는 진행하지 않는다.

특성은 키워드를 **만들거나**, 이미 있는 키워드를 **써서** 효과를 낸다. 예시 영웅 3명:

| 영웅 | 고유 특성 | 승급 1 (2택1) | 승급 2 (2택1) |
|---|---|---|---|
| 궁수 | 원거리 | 표식 사격: 맞은 적에게 [표식] / 관통: 방패 무시 | 연사 / 후퇴 사격 |
| 도적 | 빠름 | 처형: [표식] 대상에게 피해 2배 / 그림자 이동: 뒷줄로 진입 | 연속 처치 / 은신 |
| 기사 | 수호 | 도발: 주변 적을 끌어당김 / 반격 | 밀치기 / 방벽 |

- 소문 예시: "인접한 아군이 [표식] 대상을 공격하면 이 영웅도 추가 공격"처럼 특정 키워드 조합을 강화하는 교체형 카드.
- 전투 규칙(속도 순서대로 행동)은 그대로 두고, 키워드 연계가 그 위에 **배치 순서 퍼즐**을 얹는다. 예: 도적은 빠르기 때문에 같은 라운드에 궁수와 놓이면 표식이 붙기 전에 먼저 공격한다 → 1라운드 궁수로 표식, 2라운드 도적으로 처형, 그동안 기사의 도발로 돌진형 적을 묶는다.
- 단계: 준비(미리보기 보고 덱·소문·공용 트리) → 배치(속도 순서를 고려한 배치 순서) → 성장(휘장으로 어떤 영웅을 어떤 연계로 키울지).

### 1-4. 리스크 (기획서)

| 리스크 | 대응 |
|---|---|
| 작업량: 영웅 8명 × 승급 3단계 × 2택1 = 특성 48개 | 승급 2단계(영웅당 특성 4개)로 시작하거나 클래스별 특성 풀 공유 |
| 만능 연계: 표식 + 처형처럼 너무 강한 조합 | 표식이 안 통하는 적(정화형 등) 배치 |
| 재미 검증 | 영웅 3명 + 키워드 2개(표식, 도발)로 프로토타입 우선 제작 (T-15) |

## 5. 영웅 승급 — 구현됨 (2026-11-16)

### 5-1. 규칙 (「성장 시스템 기획서」 rev 21)
- 특성 칸 **2개 고정**(전투 규칙 "유닛당 최대 2개" 유지). 처음 칸 = 영웅의 고유 특성(`HeroData.Traits`).
- 최대 **2단계**, 비용 승급 1 = 휘장 1, 승급 2 = 휘장 2 (순서대로만).
- 승급마다 둘 중 하나: **새 특성**(빈 칸이 있을 때, `HeroData.PromotionTraits` 중 아직 없는 것) / **특성 강화**(강화 안 한 칸을 `TraitData.Enhanced`로 교체, 특성마다 1회). 조건을 만족하는 선택지만 보여 준다(1개면 1개).
- 승급마다 **체력 +1**(기획서 제안값). AP 비용 불변. **되돌릴 수 없음**.
- **영웅 종류 단위** — 같은 영웅 카드 여러 장은 같은 승급 상태를 공유. **보유 영웅만** 적용(스테이지 기본 제공 카드·디버그 손패 카드는 데이터 그대로).
- 전투에 들어갈 때 카드로 만든 영웅에 반영되고 전투 중에는 바뀌지 않는다.
- 두 특성이 같은 시점에 발동하면 칸 1 → 칸 2 순서 — `CombatantView.SetUpTraits`가 칸 순서로 구독하고 `ActionSystem`이 구독 순서로 호출해 코드 변경 없이 충족.

### 5-3. 승급 특성 데이터 (기획서 예시 4명, `1_Datas/3.Traits/`, Id 3016~3027)

| 영웅 | 고유 → 강화형 | 승급 특성 → 강화형 |
|---|---|---|
| 견습기사 | 없음 | 투지(기존 3010) → 투지+ 3020 (공+1·체+1) / 방어 태세 3016 (배치 시 회피 1) → 방어 태세+ 3021 (회피 2) |
| 매복자 | 빠른 발 → 빠른 발+ 3022 (공+2·속+2) | 기습 3017 (빠른 발 발동 시 치명타 1) → 기습+ 3023 (치명타 2) |
| 나팔수 | 공격 신호 → 공격 신호+ 3024 (속도 소모 1) | 진군 나팔 3018 (추가 공격마다 주변 8칸 아군 무작위 1명 힘 1) → 진군 나팔+ 3025 (2명) |
| 기병 | 맹공 → 맹공+ 3026 (전투당 6회) | 기세 3019 (적 용병 처치 시 체력 +1) → 기세+ 3027 (체력 +2) |

- **기습**은 새 조건 없이 빠른 발과 같은 조건(`SelfPlacedCondition`, `requireNoOpponentInFront`)을 써서 같은 순간에 발동한다 — 빠른 발 조건을 바꾸면 기습·기습+도 함께 바꿔야 한다.
- 새 부품: `ExtraAttackCondition`, `KilledOpponentCondition`, `AddStatusNearbyAlliesEffect` — [Trait/trait.md](Trait/trait.md) 표에 등록.
- 그림은 임시(비슷한 특성 에셋을 복사) — 방어 태세 계열(요새화 복사)·진군 나팔/공격 신호+ 계열은 원본에 그림이 없어 비어 있음.

### 5-4. 검증 (Play)
- 승급 경로·비용: 휘장 10개로 5회 승급(1+1+1+1+2) → 4개 남음. 휘장 부족·이미 쓴 선택지 재사용은 거부.
- 전투 발동: 방어 태세(배치 시 회피 1, 체력 3+2), 기습(빠른 발과 함께 치명타 1), 진군 나팔(추가 공격 → 옆 칸 아군 힘 1), 기세(적 처치 → 체력 +1, 장애물·용병대장 처치에는 미발동) 확인.
- 강화형 8개는 데이터·선택지만 확인, 전투 발동은 미확인.
- 화면: 목록·상세·2택1·확인 팝업 표시 확인. 확인 버튼으로 실제 승급까지 가는 흐름은 Play 확인 중 테스트 스크립트 문제로 에디터가 멈춰 미확인.
