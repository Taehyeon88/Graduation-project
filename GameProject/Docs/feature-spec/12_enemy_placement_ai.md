# 12. 적 AI 배치

> 원칙: **"순서는 디자이너, 위치는 AI"**. 웨이브 안의 배치 순서는 고정하고, AI는 상황에 맞는 위치만 판단한다. 배치 이후 적 행동은 규칙(속도순 자동 전투)으로 예측 가능하다.
> 원본: Claude Docs [「졸업작품 기획 결정 정리 — 스테이지형 전환」](https://claude.ai/artifact/Jze3unwnJ26XAPB113egh5)(rev 16) "다듬는 중: AI 배치". 구현 항목: [task-list.md](../task-list.md) T-06~T-09.
> **상태: 뼈대 (미구현, 기획 결정 반영 2026-11-16)** — 각 T 항목 착수 시 이 문서를 구체화한다.

**적 행동에는 랜덤이 없다.** 같은 판세면 항상 같은 결과가 나온다. 재도전은 같은 몬스터 구성·순서로 진행되지만, 적은 플레이어 배치에 반응하므로 지난판을 외우는 대신 패배를 분석하고 대응하게 된다. 시드 고정은 하지 않는다.

## 1. 기획

### 1-1. 디자이너가 정하는 것
- 웨이브별 몬스터 구성과 순서
- 배치 가능 구역: 맵마다 적이 등장할 수 있는 칸을 지정해 말이 안 되는 배치를 차단

### 1-2. AI가 판단하는 것 — 칸 점수
- 몬스터가 놓일 칸과 이동은 AI가 **매번 현재 판세(플레이어 배치 포함)** 를 보고 계산한다.
- 칸마다 점수를 매겨 가장 높은 칸을 선택한다. 점수가 같은 칸은 고정 규칙으로 고른다: **가장 가까운 영웅 쪽 → 왼쪽부터**.
- 결정(원본): AI는 플레이어의 현재 배치에 반응해 위치를 고른다. 웨이브 시작 시점 판세만 보는 방식은 재도전 때 적 행동을 외울 수 있어 제외했다.
- 점수 = 특징별 가중치의 합 (거리, 사거리 확보, 위협받는 정도, 아군 인접, 위험 지형 회피 등)
- 몬스터별 역할 프로필:

| 역할 | 선호 위치 |
|---|---|
| 돌진형 | 앞줄, 약한 영웅 근처 |
| 원거리형 | 사거리가 확보되는 후열 |
| 소환사·버퍼 | 아군 근처의 안전한 칸 |

- 몬스터를 추가할 때 가중치 표만 만들면 된다(1인 개발 관리 용이).

### 1-3. 난이도
- 쉬움: 최고 점수 대신 2등 칸 선택, 또는 쉬움 전용 가중치 표 사용
- 어려움: 항상 최고 점수 칸 선택

### 1-4. 정보 공개 · 개발 도구
- 다음 웨이브의 몬스터 목록과, 가능하면 등장 구역까지 미리 표시
- 칸별 점수를 히트맵으로 보여주는 디버그 모드

## 2. 현재 코드 상태 (관찰, 2026-11-16)

| 위치 | 현재 동작 |
|---|---|
| `WaveData.cs` | `EnemyDatas`(몬스터 리스트), `WavePerEnemyCount`(웨이브당 수), `WaveTurnIntervals`(대기 턴, index 0 미사용), `SpawnLines`(몬스터별 생성 라인 y, 고정) |
| `WaveSystem.cs` | 첫 웨이브는 전투 시작 전, 이후 플레이어 턴 시작 PRE마다 카운트 확인 → `SpawnWaveGA`. `BuildSpawn`: 라인의 적 배치 위치에 생성, 위치가 없거나 점유되면 **생성하지 않음**(경고 로그) |
| `EnemySystem.cs` | `SetupPoses`: 적 배치 가능 위치(라인당 1개, 중립지대에 따라 한 칸 앞으로, 전투 중 불변). 몬스터 턴 행동 없음 |
| `VisualGridCreator` | 타일 하이라이트 API — 히트맵 표시에 재사용 후보 ([09_visual_grid.md](09_visual_grid.md)) |

## 4. 결정 필요 · 보류

- 쉬움 난이도: "2등 칸 선택"과 "쉬움 전용 가중치 표" 중 무엇을 쓸지 (결정 필요)
- 동점 규칙 "왼쪽부터"의 기준: 그리드 좌표(x 또는 y가 작은 쪽)인지, 화면상 왼쪽인지 (결정 필요)
- AI 판단 범위: 원본은 "몬스터가 놓일 칸과 **이동**은 AI"라고 한다. 현재 몬스터 이동은 자동 전투 규칙(`CombatantView.Battle`: 정면 1칸 전진)이다. 이동까지 AI로 바꾸는지, 소환 위치만 AI인지 (결정 필요 — 이동을 바꾸면 원작 전투 규칙과 달라짐)
- AI 판단 시점: 웨이브 소환 때마다 그 시점의 판세로 계산하는지 (결정 필요)
- 배치 가능 구역 범위: 현재 규칙(적 배치 구간 = 라인당 1칸, 기본 x=3) 안에서만 고르는지, 더 넓은 칸을 허용하는지 (결정 필요)
- 구역이 점유돼 생성 못 하는 몬스터를 현재처럼 버릴지, 다음으로 미룰지 (결정 필요)
- 가중치 특징 목록·수치 (보류 — 기획서 "다음 단계": 몬스터 역할 프로필과 칸 점수 가중치 표 초안 작성)
