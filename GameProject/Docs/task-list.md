## Phase 2 — 진행 구조 B안
> ✅ **구현 완료, 플레이 검증 전 (2026-11-16)** — **T-02·T-03·T-04·T-05(스테이지 선택 쪽 미리보기)는 「스테이지 선택 시스템」 한 작업으로 통합** — Claude Docs [「스테이지 선택 시스템 기획서」](https://claude.ai/artifact/Au9KNHFbg3zE38iDk7v4JP) 기준, 상세는 [11_stage_progress.md](feature-spec/11_stage_progress.md). 아래 T-02~05 원문은 기록용이며 시드·용병대장 체력 관련 서술은 낡았다. T-05의 "전투 중 다음 웨이브 표시"는 통합 범위 밖으로 남는다.

**T-02 스테이지 진행 상태로 `GameSystem` 개편**
- 런 상태(`CurrentStageLevel` 1자 진행) → 스테이지별 진행 기록(클리어 여부, 첫 클리어 여부, 획득 별). 보유 영웅 로스터(`Deck` → 로스터 + 편성 덱 분리).
- 패배 시 `StartFromScratch` 대신 **같은 스테이지 재도전**(같은 시드). 승리 시 스테이지 선택으로 복귀.
- 용병대장 체력 런 이월(`HeroCaptainHealth`) → **결정 필요**: 스테이지마다 초기화로 바꿀지.
- 완료 기준: 패배 → 재도전 버튼 → 동일 초기 상태로 같은 스테이지 재시작.

**T-03 스테이지 선택 해금 구조**
- `StageSelectSystem`: `CurrentStageLevel` 의존 1자 선택 → 클리어 기록 기반 해금 + 클리어한 스테이지 재방문(별 회수용).
- 완료 기준: 클리어한 스테이지 재진입 가능, 미해금 스테이지 선택 불가.

**T-04 덱 편성 (기본 영웅 + 선택 영웅)**
- `StageData`에 기본 영웅 목록 추가(고정 스탯·승급 상태·특성을 담은 프리셋 — T-10의 승급 모델에 의존), 덱 슬롯 수(5~8 범위, 공용 트리 "덱 슬롯 +1" 반영 지점).
- 신규 편성 단계(시스템 + 에디터에서 만들 UI): 로스터에서 선택 → 편성 덱을 `CardSystem` 드로우 더미로 전달.
- 완료 기준: 편성한 덱만으로 전투 시작, 기본 영웅은 빼지 못함(결정 필요 시 표기).

**T-05 몬스터·맵 미리보기**
- 스테이지 선택 툴팁(`StructureView`)에 등장 몬스터 풀 + 맵(중립지대·장애물·발판) 표시.
- 전투 중 다음 웨이브 몬스터 목록(가능하면 등장 구역) 표시.
- 완료 기준: 선택 전에 몬스터·맵, 전투 중 다음 웨이브를 확인 가능.

## Phase 3 — 적 AI 배치 ("순서는 디자이너, 위치는 AI")
**T-06 웨이브·스테이지 데이터 개편**
- `WaveData.SpawnLines`(몬스터별 고정 라인) → 웨이브별 **배치 순서 고정** 몬스터 리스트. `StageData`에 맵별 **적 배치 가능 구역**(칸 목록) 추가.
- 현재 규칙(라인당 적 배치 위치 1칸, 점유 시 소환 안 됨 — `WaveSystem.BuildSpawn`)과 구역 방식의 관계 → **결정 필요**: 구역이 적 배치 구간(x=3 라인) 안의 칸만인지, 더 넓은지.

**T-07 역할 프로필 + 칸 점수 AI**
- 신규 `EnemyRoleProfileData`(SO: 특징별 가중치 표 — 거리, 사거리 확보, 위협도, 아군 인접, 위험 지형 회피). `EnemyData`에 프로필 참조.
- 신규 배치 로직(`EnemyPlacementSystem` 또는 `WaveSystem` 확장 — 착수 시 결정): 후보 칸 점수 = 가중합, 최고점 선택, 동점은 시드로.
- 판단 시점(플레이어 현재 배치 반영 vs 웨이브 시작 판세) — 기획서의 **열린 질문**, 착수 전 결정 필요.
- 완료 기준: 같은 시드·같은 판세 → 같은 칸.

**T-08 난이도 옵션**: `StageData`에 난이도(쉬움 = 상위 2~3칸 중 시드 선택 / 어려움 = 최고점).

**T-09 디버그 히트맵**: 칸별 점수를 `VisualGridCreator`로 표시하는 디버그 모드(`10_cheat_mode.md` 치트 모드와 같은 토글 체계).

## Phase 4 — 성장 시스템
> **진행 (2026-11-16)**: T-10·T-11은 Claude Docs 「성장 시스템 기획서」(rev 21) 기준으로 **구현됨** — 특성 칸 2개 유지, 승급 2단계, 새 특성/강화 2택1 (아래 원래 항목의 "고유 1 + 승급 2~3"·`PromotionData`·`MaxTraitCount` 변경안과 다름). 상세 [13_growth.md](feature-spec/13_growth.md) §5. T-15는 기획서에 키워드가 빠져 **진행 안 함**.

**T-10 영웅 특성 구조 개편 (고유 1 + 승급)** — ✅ 구현됨 (13_growth.md §5)
- `HeroData`: 고유 특성 1개 + 승급 단계별 2택1 후보(신규 `PromotionData` 또는 필드). 단계 수 2/3은 **보류 사항** → 데이터로 열어두지 말고 착수 시 1개로 정해 구현.
- `Hero`: 승급 단계·선택 특성 보관. `MaxTraitCount=2` 제약을 영웅에 맞게 변경(몬스터·장애물 기존 특성은 유지).
- 완료 기준: 승급 선택한 특성이 전투에서 발동.

**T-11 승급 휘장** — ✅ 구현됨 (휘장 지급은 기존 `RecordClear`, 사용·승급 화면은 `PromotionSystem`/`PromotionUI`): 스테이지 **첫 클리어**에 휘장 지급(총량 고정, 지급량은 보류 → 임시값 표기), 승급 화면(2택1). `RewardSystem` 대체 범위는 C6 결정에 따름.

**T-12 별 목표 + 공용 트리** — ✅ 공용 트리 구현됨 (2026-11-17, 「성장 시스템 기획서」 rev 27: 본부 + 4가지 + 혼합 노드 그물, 노드 27개·78레벨, 레벨당 별 1, 전체 초기화만). 효과는 15개 구현, 12개는 "준비 중"(구매 불가). 아래 원래 항목의 예시 노드("원거리 사거리 +1"·"전투 중 리롤")는 rev 27에서 빠짐. 상세 [13_growth.md](feature-spec/13_growth.md) §6. 별 목표·기록은 기존 `StarSystem`/`RecordClear`(T-02).
- 스테이지별 별 목표(종류는 보류 → 최소 1~2종 임시) → 별 획득 기록(T-02).
- 신규 공용 트리 데이터·시스템: 노드 = 클래스 공통 효과/덱 규칙, 언제든 무료 재배분.
- 예시 노드의 전제: "원거리 사거리 +1"은 **현재 사거리 개념 없음**(정면 1칸 + 저격 특성) → 사거리 스탯 신설 필요, "전투 중 리롤 +1"은 **리롤 기능 자체가 없음** → 무엇을 리롤하는지 결정 필요. 프로토타입은 "덱 슬롯 +1", "소문 칸 해금"부터.

**T-13 소문 교체형으로 전환**: `Hero.AddRumor`(획득 후 고정) → 스테이지 전 준비 단계에서 교체 가능. `TavernSystem` 흐름과의 관계는 C6 결정.

**T-14 준비 단계 화면 흐름**: 스테이지 선택 → 준비(덱 편성 T-04 · 소문 교체 T-13 · 트리 재배분 T-12) → 전투 → 결과(휘장·별) → 성장(T-11). 씬/UI 배치는 에디터 작업으로 안내.

## Phase 5 — 키워드 연계 프로토타입 (기획서 "다음 단계" 1순위)
**T-15 키워드 2종 + 영웅 3명** — ❌ 진행 안 함 (「성장 시스템 기획서」 rev 21에 키워드 없음)
- `표식`(신규 `StatusEffectType` — 값은 기존 정수 고정 규칙 따라 7 이후), `도발`(주변 적 끌어당김 — `KnockBackProcessor` 역방향 재사용 검토).
- 궁수(원거리 고유 + 표식 사격), 도적(빠름 + 처형: 표식 대상 피해 2배), 기사(수호 + 도발) — `/trait`, `/status_effect` 커맨드로 부품 레지스트리 대조 후 추가.
- 관통(방패 무시)은 **방패 개념 없음** → 프로토타입에서 제외하거나 정의 필요.
